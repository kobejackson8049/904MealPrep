1. PAYMENT METHODS

Square should remain the visually preferred/default payment method.

Also support:

* Cash App
* Zelle
* Venmo

Apple Pay may be available through the integrated payment provider where supported.

All payment methods MUST create orders in the SAME normalized order system.

⸻

2. MANUAL PAYMENT WORKFLOW

Cash App, Zelle and Venmo are considered manual/external payment methods because the business owner may need to verify receipt outside the website.

Customer should still complete the normal checkout process:

1. Select meals
2. Choose pickup/delivery
3. Enter customer information
4. Select payment method
5. Review order
6. Submit order

If Cash App, Zelle or Venmo is selected, show a dedicated payment instruction screen.

⸻

Underneath, show:

What name will the payment come from?

Please include Order #904-1057 in your payment note when possible.

4. ZELLE AND VENMO

Use the same workflow for:

Zelle

Display:

* configured Zelle email/phone
* optional uploaded Zelle QR code
* amount due
* order number
* sender/account name input

Venmo

Display:

* configured Venmo handle
* optional Venmo QR code
* amount due
* order number
* sender/account name input

The owner should configure all payment handles and QR codes from Admin Settings.

Do NOT hardcode them into components.

⸻

5. QR CODE SUPPORT

Add payment settings in:

/admin/settings

Allow owner to configure:

Cash App

* Cash App tag
* Upload Cash App QR code
* Enable/disable Cash App

Venmo

* Venmo handle
* Upload Venmo QR code
* Enable/disable Venmo

Zelle

* Zelle phone/email
* Upload Zelle QR code if their financial institution provides one
* Enable/disable Zelle

Do NOT assume every payment service has a universally generated QR format.

Prefer allowing the business owner to upload the official QR code produced by their actual payment service/account.

Store these files using the same portable persistent media-storage architecture as other admin uploads.

Do NOT use temporary Replit file URLs.

7. MANUAL PAYMENT CUSTOMER INFORMATION

When Cash App/Zelle/Venmo is chosen, collect:

Payment sender name

This means:

The name the owner should expect to see in Cash App, Venmo, or Zelle.

Store it on the payment record.

Example database information:

* Order: #904-1057
* Customer: Emily Carter
* Payment method: Cash App
* Amount: $64
* Expected sender name: Emily Carter
* Payment status: Payment Pending

IMPORTANT:

The sender name is ONLY a reconciliation aid.

Do NOT automatically mark an order paid merely because the customer typed a name.

Owner verification is still required.

16. SQUARE AUTOMATION

Square should work differently because successful integrated payments can be verified by the payment provider.

Successful Square payment:

* Create/update order
* Payment = Paid
* Order = Confirmed
* Send confirmation email
* Update analytics automatically

Manual owner confirmation should NOT be necessary when the Square provider has securely confirmed successful payment.

⸻

17. ORDER VS PAYMENT VS FULFILLMENT STATUS

Keep these concepts separate.

PAYMENT STATUS

* Payment Pending
* Paid
* Failed
* Refunded

ORDER STATUS

* Awaiting Payment Confirmation
* Confirmed
* Cancelled

FULFILLMENT STATUS

* Not Started
* Preparing
* Packed
* Ready for Pickup
* Out for Delivery
* Picked Up
* Delivered

Do NOT use one status field for everything.

This is very important.

Clearly distinguish demo email behavior from actual delivered production emails.

* Cash App passwords
* Venmo passwords
