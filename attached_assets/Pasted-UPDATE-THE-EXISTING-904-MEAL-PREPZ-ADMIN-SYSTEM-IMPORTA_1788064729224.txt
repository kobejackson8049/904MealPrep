1. IMPROVE WEEKLY MENU MANAGEMENT

The current /admin/weekly-menu page looks too much like a simple list.

Turn this into a true weekly menu management workspace.

The admin should be able to see every active/non-archived meal from the Meal Library and easily choose which meals will be available to customers for the current week.

Each meal should have a clear LIVE/OFF toggle or checkbox.

Example:

[✓] 3 Egg Breakfast — LIVE

[✓] Teriyaki Chicken Bowl — LIVE

[✓] Jerk Chicken Bowl — LIVE

[ ] Chicken Alfredo — OFF

[ ] Taco Bowl — OFF

[✓] Smoky Salmon Bowl — LIVE / PREMIUM

Clearly distinguish:

* Standard meal
* Premium meal
* Breakfast
* Lunch
* Dinner

Admin should be able to build the next weekly menu WITHOUT immediately changing what customers see.

Add these actions:

* Save Draft
* Preview Customer Menu
* Publish Menu

Only clicking Publish Menu should make the new weekly selection live on the customer-facing website.

Until publishing, customers should continue seeing the currently published menu.

When a new menu is published, the previous menu should remain preserved in historical records.

Add a confirmation before publishing:

Publish this menu to customers?

7. FIX ALL DEMO DATA CONSISTENCY

This is extremely important.

The current seeded/demo data appears to contain numbers that do not fully reconcile between Dashboard, Orders, Kitchen Prep, Analytics and Payments.

Fix this.

Create ONE normalized seeded dataset and derive ALL admin numbers from it.

DO NOT hardcode unrelated numbers into individual pages.

Every page should calculate from the same:

* customers
* orders
* order items
* meals
* payment records
* fulfillment records

For example:

If Dashboard says:

6 weekly orders

and

28 meals sold

then:

* Orders should contain exactly those 6 active orders.
* The quantities of all order items should add up to exactly 28.
* Kitchen Prep quantities should add up to exactly 28.
* Customer histories should reflect those same 6 orders.
* Revenue should equal the actual paid orders.
* Pending payment total should equal the actual pending orders.
* Payment-method totals should reconcile to revenue.
* Delivery revenue should reconcile with delivery charges from those orders.

Build reusable calculation utilities/selectors rather than repeating hardcoded calculations throughout the UI.
